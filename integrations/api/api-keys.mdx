title: API keys

description: "Create and manage the API keys that let your tools and scripts securely act on one of your Linkzee stores."
---

An **API key** is how your tools, scripts and AI agents prove they're allowed
to act on your Linkzee. You create keys yourself, give each one the access it
needs, and revoke any key the moment you no longer trust it.

Each key belongs to **one store**. If your account holds more than one store,
the key acts on the store you were in when you created it, and never touches the
others — see [Multiple stores](/account/multiple-stores).

## Create a key

<Steps>
  <Step title="Switch to the right store">
    The key is created for the store that's **active** in the sidebar, so pick
    that store before you start.
  </Step>
  <Step title="Open your settings">
    In your dashboard settings, open the **API & MCP** section.
  </Step>
  <Step title="Create a new key">
    Create a key and choose the access it should have. Every key starts with
    `lzk_` so it's easy to recognize.
  </Step>
  <Step title="Copy it right away">
    Copy the key while it's shown and store it somewhere safe — treat it like a
    password. Paste it into the tool or agent you want to connect.
  </Step>
</Steps>

## Scopes

Each key carries a **scope** that decides what it can do:

| Scope | What it allows |
| --- | --- |
| **read** | List and read your data |
| **write** | Create, update and delete |
| **finance** | Financial reports (like your earnings summary) |

Give a key only the access it needs. If a tool just displays your data, a
**read** key is enough; a key that changes your page or products needs **write**.
**finance** is never included by default — you add it explicitly when creating
the key, and rotating a key keeps exactly the scopes it had. Consolidated
earnings are the kind of access you grant on purpose.

## Revoke a key

You can revoke a key anytime from the same **API & MCP** section. Revoking takes
effect immediately and instantly stops any tool still using that key, so it's
the fastest way to cut off access if a key is ever exposed or no longer needed.

<Note>
  The **API & MCP** section lists the keys of the store you're in. To see, rotate
  or revoke another store's key, switch to that store first. Rotating a key keeps
  it on its own store, so your integration never moves to a different one.
</Note>

<Warning>
  Never share your key or put it in public code — anyone who has it can act on
  the store it belongs to. If a key leaks, revoke it right away and create a new
  one.
</Warning>
