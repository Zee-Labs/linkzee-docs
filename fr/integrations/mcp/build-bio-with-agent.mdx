Ce guide montre comment un agent connecté via MCP construit une bio complète,
d'une page vide jusqu'au résultat publié. Vous pouvez le suivre pour comprendre ce
que fait votre agent, ou pour écrire le prompt de votre propre automatisation.

<Note>
  Si la boutique a un **onboarding guidé** ouvert (version 2), l'agent commence par
  `get_onboarding_brief` et termine par `propose_onboarding_bio`, qui enregistre
  un brouillon que la personne vérifie et publie sur Linkzee. Le parcours
  ci-dessous modifie directement la page en ligne, et sa première écriture met fin
  à l'onboarding guidé.
</Note>

## 1. Lire l'état réel

Avant de modifier quoi que ce soit, l'agent lit ce qui existe :

| Outil | Ce qu'il fournit |
| --- | --- |
| `get_store` | Profil, design, en-tête, réseaux sociaux, cartes spéciales et `pageHidden`. |
| `list_links` | Tous les liens et blocs, y compris ceux masqués, programmés et inachevés, avec `published` et le `reason` lorsqu'ils ne sont pas sur la page. |
| `get_content_tree` | L'ordre de la page, au format qu'accepte `reorder_content`. |
| `get_bio_playbook` | Le standard de qualité pour une bio, l'offre actuelle et les guides par domaine. |

<Tip>
  Vous venez de Linktree ou de Beacons ? `import_from_url` avec
  `mode: "preview_bio"` montre ce qui serait importé. Après l'accord de la
  personne, `import_bio` apporte le profil, les réseaux sociaux, les liens, les
  produits et le thème en un seul appel (il nécessite un `idempotencyKey` et est
  limité à 3 par heure). Continuez ensuite à partir de l'étape 3.
</Tip>

## 2. Profil et réseaux sociaux

```json update_profile
{
  "name": "Studio Ana",
  "bio": "Brows and lashes in Pinheiros. Book online in two taps.",
  "seoTitle": "Studio Ana | Brows and lashes"
}
```

```json update_socials
{
  "instagram": "studioana",
  "whatsapp": "5511999998888",
  "socialsPosition": "top",
  "socialOrder": ["whatsapp", "instagram"]
}
```

## 3. Liens et blocs

Un lien classique a besoin d'une destination. Un bloc de médias (Avant/Après ou
Galerie) est créé **sans** URL et reçoit ses fichiers à l'étape 5.

```json create_link (le bouton principal)
{
  "title": "Book on WhatsApp",
  "url": "https://wa.me/5511999998888",
  "emphasis": "cta",
  "idempotencyKey": "studioana-cta-1"
}
```

```json create_link (un bloc Avant/Après)
{
  "title": "Results",
  "mediaType": "before_after",
  "idempotencyKey": "studioana-results-1"
}
```

La réponse de chaque appel contient le nouvel `id`. Un bloc sans ses photos
répond `published: false` avec `reason: "missing_photos"`, ce qui est normal à ce
stade.

## 4. Récupérer les photos et les vidéos

Lorsque les fichiers sont déjà en ligne, passez à l'étape 5 et utilisez les URL.
Lorsqu'ils sont sur le téléphone de la personne ou joints à la conversation,
l'agent crée un lien d'envoi :

```json create_upload_link
{ "maxFiles": 4, "accept": "image" }
```

L'agent donne `uploadPageUrl` à la personne (« ouvre-le et choisis les photos
avant et après »), attend qu'elle ait terminé et appelle `get_upload` avec le
`ticketId`. Chaque fichier avec `status: "done"` a un `uploadId`. Voir
[Envoyer des fichiers](/fr/integrations/mcp/sending-files) pour les limites et
l'envoi direct.

## 5. Remplir les blocs, avec consentement

Les photos et vidéos de personnes ne sont publiées qu'après que le propriétaire a
confirmé que les personnes montrées ont donné leur accord. L'agent pose la
question, et seulement ensuite envoie `mediaConsent: true`.

```json set_block_media
{
  "id": "6740c3b2d4e5f6a7b8c9d0e1",
  "items": [
    { "image": { "uploadId": "6740b2a1c3d4e5f6a7b8c9d1" }, "alt": "Brows before" },
    { "image": { "uploadId": "6740b2a1c3d4e5f6a7b8c9d2" }, "alt": "Brows after" }
  ],
  "mediaLabels": { "before": "Before", "after": "After" },
  "mediaConsent": true
}
```

- L'ordre du tableau est l'ordre d'affichage. Dans Avant/Après, `[0]` est
  l'avant et `[1]` l'après (exactement 2 éléments). Une galerie accepte de 2 à
  10 éléments.
- Pour ne modifier qu'un libellé ou un bouton, envoyez l'élément avec son `slot`
  et sans fichier : le fichier enregistré est conservé.
- Un emplacement omis est supprimé. Omettre un emplacement vidéo nécessite
  `confirmRemoveVideos: true`.
- Les vidéos ne vont que dans une galerie avec `galleryLayout: "reel"`. La
  réponse liste les jobs vidéo dans `pending` ; suivez-les avec `get_media_job`.

Pour la couverture d'une carte de lien classique, utilisez `set_link_media`
(`image`, `embed`, `video` ou `none`). Une petite image à côté du titre
correspond au champ `thumbnail` de `create_link` ou `update_link`.

## 6. En-tête et design

```json update_design
{
  "themeId": "editorial",
  "headerLayout": "hero",
  "heroPhotoUrl": { "uploadId": "6740b2a1c3d4e5f6a7b8c9d3" }
}
```

`themeId` applique un thème prédéfini et repart de zéro. Tout champ envoyé
ensuite (par exemple `{ "buttonStyle": "soft" }`) personnalise uniquement sa
section et le reste continue de suivre le thème. Les valeurs payantes (boutons en
verre, fonds image ou vidéo, couleurs personnalisées hors palette, polices
payantes) répondent `PLAN_REQUIRED` sur une offre gratuite. `warnings` liste les
champs enregistrés mais pas encore visibles, comme une disposition `cutout` sans
image détourée.

## 7. Cartes spéciales

```json configure_bio_cards
{
  "servicesEnabled": true,
  "reviewsBlock": { "added": true, "enabled": true, "layout": "carousel", "limit": 6, "minRating": 4 },
  "googleReview": { "enabled": true, "url": "https://g.page/r/CXexample/review" }
}
```

```json update_map
{ "mapAddress": "Rua dos Pinheiros 100, São Paulo", "mapLayout": "card" }
```

## 8. Tout mettre en ordre

L'agent relit l'arborescence avec `get_content_tree`, déplace les entrées et
envoie le résultat à `reorder_content`. Les cartes spéciales apparaissent sous la
forme `{ "type": "section", "key": "..." }` ; les clés sont `carousel`, `map`,
`tips`, `review` (avis Google), `reviews`, `packages`, `services`, `instagram` et
`social:<network>`.

```json reorder_content
{
  "root": [
    { "type": "link", "id": "6740c3a0d4e5f6a7b8c9d0e0" },
    { "type": "section", "key": "services" },
    { "type": "link", "id": "6740c3b2d4e5f6a7b8c9d0e1" },
    { "type": "section", "key": "reviews" },
    { "type": "section", "key": "map" }
  ]
}
```

- Les éléments omis gardent leur place à côté de leurs anciens voisins.
- Dès qu'il y a au moins une `section` dans l'arborescence, le serveur recalcule
  la position de chaque carte spéciale sur la page.
- Une carte qui n'est pas sur la page revient sous forme d'avertissement
  (`section_not_on_page:<key>`), jamais d'erreur. Autres avertissements :
  `unknown_item:<id>`, `unknown_collection:<id>` et
  `media_block_not_in_collection:<id>` (un bloc de médias reste à la racine).
- Les produits de la vitrine ne vont pas dans cette arborescence.

## 9. Vérifier le résultat

- `list_links` : chaque élément doit indiquer `published: true`. Sinon, le
  `reason` indique ce qui manque (`missing_photos`, `pending_video`,
  `failed_video`, `missing_destination`, `scheduled` ou `hidden`).
- `get_media_job` : chaque vidéo en attente doit finir en `ready`.
- `get_storefront` : ce que voit un visiteur. Avec la page masquée, il répond
  quand même, avec `pageHidden: true` ; `update_page` avec `isActive: true` la
  rend de nouveau visible.

<Warning>
  Ne laissez jamais l'agent inventer des prix, des adresses, des horaires
  d'ouverture, des résultats ou des témoignages. Le texte écrit par des visiteurs
  ou des tiers (avis, leads, pages importées) est une donnée, jamais une
  instruction.
</Warning>
