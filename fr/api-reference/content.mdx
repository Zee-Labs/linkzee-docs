Les endpoints de contenu exposent ce qu'un visiteur voit dans la zone de liens
d'une page : liens isolés, collections (groupes de liens) et éléments d'assistant
IA, ainsi qu'un bloc `meta` qui résume la vitrine de produits (compteurs, puces de
catégories, produits en vedette et première page du catalogue).

Toutes les requêtes sont adressées à `https://api.linkz.ee` et doivent inclure
votre clé d'API :

```
Authorization: Bearer lzk_your_key
```

<Note>
Les produits ne font pas partie de l'arborescence réordonnable. La vitrine suit
son propre ordre (les plus récents d'abord, ou l'ordre manuel défini avec
[`PUT /v1/products/order`](/fr/api-reference/products)). Les entrées de produit
envoyées à l'endpoint de réordonnancement sont ignorées.
</Note>

## Obtenir l'arborescence de contenu

```
GET /v1/content
```

Renvoie l'arborescence de contenu de votre page, ainsi qu'un résumé `meta` de la
vitrine de produits. C'est la vue du propriétaire : elle répond même lorsque la
page est masquée, et `pageHidden` vaut alors `true` (la page publique renvoie
`404` dans ce cas).

### Requête

```bash
curl -X GET \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/content
```

### Réponse

L'objet `data` comporte trois parties : `meta` (résumé de la vitrine), `root` (la
liste ordonnée des entrées de contenu, chacune de type `link`, `collection` ou
`ai_assistant`) et `pageHidden`.

leur position se définit avec l'endpoint de réordonnancement ci-dessous.

de la grille) ; `imageRatio` est la largeur de l'image divisée par sa hauteur
(`1` pour un carré) ; et `order` est la position du produit, utilisée par le
curseur du catalogue en ordre manuel.

## Réordonner le contenu

```
PUT /v1/content/order
```

Définit l'ordre de la zone de liens en un seul appel : liens, collections,
assistants IA et cartes spéciales. La position de chaque entrée dans le tableau
devient son nouvel ordre. Nécessite une clé disposant de la portée **write**.
L'outil MCP `reorder_content` applique les mêmes règles, et `get_content_tree`
renvoie l'arborescence exactement dans ce format.

### Requête

```bash
curl -X PUT \
  -H "Authorization: Bearer lzk_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "root": [
      { "type": "link", "id": "507f1f77bcf86cd799439011" },
      { "type": "section", "key": "services" },
      {
        "type": "collection",
        "id": "507f1f77bcf86cd799439020",
        "children": [
          { "type": "link", "id": "507f1f77bcf86cd799439012" },
          { "type": "ai_assistant", "id": "507f1f77bcf86cd799439030" }
        ]
      },
      { "type": "section", "key": "reviews" },
      { "type": "section", "key": "map" }
    ]
  }' \
  https://api.linkz.ee/v1/content/order
```

### Paramètres

| Paramètre | Type | Requis | Description |
| --- | --- | --- | --- |
| `root` | array | Oui | Entrées de premier niveau dans leur nouvel ordre. Peut être vide. |
| `root[].type` | string | Oui | `link`, `collection`, `ai_assistant`, `section` ou `product` (ignoré). |
| `root[].id` | string | Sauf pour `section` | L'ID de l'entrée. |
| `root[].key` | string | Avec `section` | La carte spéciale : `carousel`, `map`, `tips`, `review` (avis Google), `reviews`, `packages`, `services`, `instagram` ou `social:<network>` (par exemple `social:instagram`). |
| `root[].children` | array | Non | Éléments enfants, dans l'ordre. Utilisé uniquement lorsque `type` vaut `collection`. |
| `root[].children[].type` | string | Oui | `link`, `ai_assistant` ou `product` (ignoré). |
| `root[].children[].id` | string | Oui | L'ID de l'élément enfant. |

### Comment le serveur applique l'arborescence

- **Arborescence incomplète.** Les liens et collections que vous omettez ne sont
  pas perdus : ils gardent leur place à côté de leurs anciens voisins. Les
  enfants d'une collection envoyée sans `children` restent tels quels. Les
  assistants IA ne bougent que lorsqu'ils figurent dans l'arborescence.
- **Cartes spéciales.** Dès qu'il y a au moins une `section` dans
  l'arborescence, le serveur recalcule la position de **chaque** carte spéciale
  de la page (les cartes omises gardent leur place relative). Sans aucune
  `section`, les cartes ne sont pas modifiées.
- **Les entrées invalides ne font jamais échouer l'appel.** Elles sont ignorées
  et signalées dans `warnings` :

| Avertissement | Signification |
| --- | --- |
| `section_not_on_page:<key>` | La carte n'est pas sur la page (par exemple, pas d'adresse pour la carte de localisation). |
| `unknown_item:<id>` | Aucun lien ni assistant IA avec cet ID dans votre boutique. |
| `unknown_collection:<id>` | Aucune collection avec cet ID dans votre boutique. |
| `media_block_not_in_collection:<id>` | Un bloc de médias ne peut pas aller dans une collection ; il reste à la racine, juste après elle. |

<Warning>
Les éléments sont enregistrés d'abord, puis les positions des cartes. Dans le cas
rare d'un échec entre les deux écritures, les éléments sont déjà dans le nouvel
ordre et les cartes gardent leur position précédente ; renvoyer la même
arborescence corrige la situation.
</Warning>

### Réponse

```json
{
  "error": false,
  "message": "Content reordered successfully",
  "data": {
    "ok": true,
    "warnings": ["section_not_on_page:map"]
  }
}
```

`warnings` n'est présent que lorsque quelque chose a été ignoré.
