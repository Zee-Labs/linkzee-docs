Utilisez l'endpoint d'envoi de fichiers pour transmettre une image à Linkzee et
récupérer une URL permanente, hébergée sur CDN. Chaque image est convertie en
**WebP**, redimensionnée pour tenir dans 1600&nbsp;px, et servie avec une mise en
cache de longue durée, si bien que l'URL que vous recevez est prête à être
insérée directement dans un produit, un lien ou le profil de votre boutique.

L'endpoint se trouve sous l'URL de base `https://api.linkz.ee` et requiert
l'en-tête `Authorization: Bearer lzk_your_key`. Un envoi modifie votre vitrine,
il nécessite donc une clé disposant de la portée **write**.

## Envoyer une image

```
POST /v1/uploads/image
```

Envoie une seule image et retourne son URL hébergée. Transmettez la requête en
`multipart/form-data`, et non en JSON.

### Requête

```bash
curl -X POST \
  -H "Authorization: Bearer lzk_your_key" \
  -F "file=@/path/to/photo.jpg" \
  -F "kind=product" \
  -F "productId=507f1f77bcf86cd799439011" \
  https://api.linkz.ee/v1/uploads/image
```

### Paramètres

Transmettez ces valeurs sous forme de champs de formulaire multipart.

| Paramètre | Type | Requis | Description |
| --- | --- | --- | --- |
| `file` | file | Oui | L'image à envoyer. Tout format courant (JPEG, PNG, WebP, etc.), jusqu'à **8&nbsp;Mo**. Elle est convertie automatiquement en WebP. |
| `kind` | string | Non | L'emplacement auquel appartient l'image. Détermine un emplacement de stockage stable, si bien que réenvoyer le même type écrase l'image précédente au lieu de les accumuler. Voir le tableau ci-dessous. |
| `productId` | string | Non | Requis lorsque `kind` vaut `product`. Le produit auquel appartient cette image. Il doit s'agir d'un produit de votre propre boutique. |
| `linkId` | string | Non | Requis lorsque `kind` vaut `link`, `linkMedia` ou `linkPoster`. Le lien auquel appartient l'image. Il doit s'agir d'un lien de votre propre boutique. |
| `staffId` | string | Non | Requis lorsque `kind` vaut `staffAvatar`. Le membre de l'équipe auquel appartient l'avatar. |
| `socialKey` | string | Non | Requis lorsque `kind` vaut `socialCard`. Le réseau social auquel appartient la couverture de carte (par ex. `instagram`, `tiktok`, `youtube`). |

#### Valeurs de `kind`

| `kind` | À utiliser pour | À envoyer aussi |
| --- | --- | --- |
| `logo` | Le logo de votre boutique | — |
| `product` | Une image de produit | `productId` |
| `wallpaper` | Le fond d'écran de votre page | — |
| `wallpaperPoster` | Hérité — l'image d'aperçu d'un fond d'écran vidéo est désormais générée automatiquement à partir de la vidéo | — |
| `banner` | La bannière de votre en-tête | — |
| `cutout` | Une image découpée d'en-tête | — |
| `link` | Une miniature de lien | `linkId` |
| `linkMedia` | Une couverture de carte de lien | `linkId` |
| `linkPoster` | Une image d'aperçu de vidéo de lien | `linkId` |
| `aiAssistantAvatar` | L'avatar de votre assistant IA | — |
| `staffAvatar` | La photo d'un membre de l'équipe | `staffId` |
| `heroPoster` | Hérité — l'image d'aperçu d'une vidéo hero est désormais générée automatiquement à partir de la vidéo | — |
| `socialCard` | Une couverture de carte de réseau social | `socialKey` |

<Note>
Lorsque vous envoyez un `kind` (et son identifiant correspondant), l'image est
stockée à un emplacement fixe pour cette ressource, si bien qu'un nouvel envoi
remplace l'ancien. Omettez `kind` et chaque envoi obtient sa propre URL unique à
la place.
</Note>

<Warning>
Les fichiers de plus de 8&nbsp;Mo sont rejetés. Seuls les fichiers image sont
acceptés — les autres types de fichiers retournent une erreur `400 Bad Request`.
Si vous définissez `kind` sur `product` ou `link`, le `productId` ou `linkId`
correspondant doit référencer une ressource de votre propre boutique.
</Warning>

### Réponse

L'`url` est votre image hébergée. Comme les images stockées sont mises en cache
de façon agressive, l'URL se termine par un marqueur de version `?v=` qui change
à chaque envoi — utilisez toujours l'URL exacte que vous récupérez.

```json
{
  "error": false,
  "message": "Upload completed successfully",
  "data": {
    "url": "https://cdn.linkz.ee/u/abc/products/507f1f77bcf86cd799439011.webp?v=1721577600000",
    "width": 1200,
    "height": 1200,
    "format": "webp",
    "hasAlpha": false
  }
}
```

| Champ | Type | Description |
| --- | --- | --- |
| `url` | string | L'URL de l'image hébergée, avec anti-cache. |
| `width` | integer | Largeur de l'image traitée, en pixels. |
| `height` | integer | Hauteur de l'image traitée, en pixels. |
| `format` | string | Toujours `webp`. |
| `hasAlpha` | boolean | Indique si l'image possède un canal de transparence. |

<Note>
Pour associer une image envoyée à une ressource, prenez l'`url` retournée et
définissez-la sur le produit ou le lien — par exemple, passez-la comme `image`
du produit lorsque vous le créez ou le mettez à jour.
</Note>

## Envoi de vidéos (hero et fond d'écran)

```
POST /v1/uploads/video?kind=hero|wallpaper
```

Envoie une courte vidéo pour votre en-tête **Hero** ou pour le **fond d'écran**
de votre page, et l'optimise en arrière-plan. Transmettez-la en
`multipart/form-data` avec un seul champ `file` (MP4 ou MOV, jusqu'à
**40&nbsp;Mo**). Cet endpoint requiert une clé disposant de la portée **write**
et une boutique sur une offre **Premium**.

```bash
curl -X POST \
  -H "Authorization: Bearer lzk_your_key" \
  -F "file=@/path/to/clip.mp4" \
  "https://api.linkz.ee/v1/uploads/video?kind=hero"
```

| Paramètre | Où | Requis | Description |
| --- | --- | --- | --- |
| `kind` | query | Oui | `hero` pour la vidéo de l'en-tête Hero, `wallpaper` pour le fond de la page. |
| `file` | multipart | Oui | La vidéo à envoyer — MP4 ou MOV, jusqu'à **40&nbsp;Mo**. |

### Réponse

La requête retourne `200` dès que le fichier est reçu, avec un **job** qui
décrit l'optimisation, ainsi qu'une indication `pollMs` de la fréquence à
laquelle le consulter.

```json
{
  "error": false,
  "message": "Video queued for processing",
  "data": {
    "id": "66f1c2a9e4b0c1d2f3a4b5c6",
    "kind": "hero",
    "status": "queued",
    "error": "",
    "errorCode": "",
    "tries": 0,
    "result": null,
    "createdAt": "2026-10-14T12:00:00.000Z",
    "finishedAt": null,
    "pollMs": 1500
  }
}
```

| Champ | Type | Description |
| --- | --- | --- |
| `id` | string | L'identifiant du job. Utilisez-le pour suivre la progression. |
| `kind` | string | `hero` ou `wallpaper`. |
| `status` | string | `queued` → `processing` → `ready`, `failed` ou `superseded`. `superseded` signifie qu'un envoi plus récent du même type a remplacé celui-ci. |
| `error` | string \| null | Un message lisible lorsque le job a échoué. |
| `errorCode` | string \| null | Un code d'erreur stable lorsque le job a échoué. |
| `tries` | integer | Le nombre de tentatives d'optimisation. |
| `result` | object \| null | Renseigné lorsque `status` vaut `ready` — voir ci-dessous. |
| `createdAt` | string | Date de création du job (ISO 8601). |
| `finishedAt` | string \| null | Date de fin du job, le cas échéant. |

Lorsque le job est `ready`, `result` contient la vidéo optimisée — et elle est
**déjà appliquée** à votre boutique, aucun `PATCH` supplémentaire n'est donc
nécessaire :

| Champ | Type | Description |
| --- | --- | --- |
| `url` | string | L'URL hébergée de la vidéo optimisée. |
| `posterUrl` | string | L'image de couverture, générée à partir de la première image de la vidéo. |
| `durationMs` | integer | Durée de la vidéo optimisée, en millisecondes. |
| `width` | integer | Largeur en pixels. |
| `height` | integer | Hauteur en pixels. |
| `bytes` | integer | Taille du fichier optimisé. |
| `trimmed` | boolean | `true` lorsque l'original dépassait 15 secondes et a été coupé. |

### Suivre et gérer les jobs vidéo

```
GET    /v1/uploads/video/jobs/{id}
GET    /v1/uploads/video/latest?kind=hero
DELETE /v1/uploads/video/{kind}
```

- `GET /v1/uploads/video/jobs/{id}` retourne le job dans son état actuel —
  consultez-le toutes les `pollMs` millisecondes jusqu'à ce que `status` vaille
  `ready` ou `failed`.
- `GET /v1/uploads/video/latest?kind=hero` (ou `kind=wallpaper`) retourne le job
  le plus récent pour ce type, ou `null` s'il n'y en a jamais eu.
- `DELETE /v1/uploads/video/{kind}` retire la vidéo publiée (`hero` ou
  `wallpaper`) de votre page.

### Profil de sortie

Chaque vidéo est encodée selon le même profil pour démarrer instantanément sur
mobile :

| Réglage | Valeur |
| --- | --- |
| Résolution | **720p** sur le petit côté — jamais agrandie |
| Fréquence d'images | 24 i/s |
| Codec | H.264 (MP4) |
| Durée | Les **15 premières secondes** |
| Audio | Supprimé — les vidéos sont toujours muettes |
| Taille | Généralement **≤ ~3&nbsp;Mo** |

<Note>
Les vidéos de plus de 15 secondes ne sont jamais rejetées pour leur durée — elles
sont coupées, et le résultat indique `trimmed: true`. Un envoi n'est rejeté que
si le fichier dépasse 40&nbsp;Mo ou n'est pas un fichier vidéo valide.
</Note>

<Note>
`POST /v1/uploads/video` avec `kind=link` (la vidéo d'un lien) continue de
stocker le fichier brut comme avant — cette optimisation ne s'applique pas.
</Note>

## Générer une vidéo de hero avec les photos des produits

```
POST /v1/uploads/video/montage
```

Monte un court montage cinématographique avec les photos de vos produits (zooms
et panoramiques lents, fondus, environ 14 secondes) et le place dans la file
comme vidéo de **hero** — même job et même suivi que l’envoi, appliqué au hero
une fois prêt. Utilise les produits les plus récents ayant une photo, ou ceux
passés dans `productIds` (jusqu’à 6, dans l’ordre). Nécessite une clé avec la
portée **write**, une boutique **Premium** et au moins 3 produits avec une photo
hébergée sur Linkzee.

```bash
curl -X POST \
  -H "Authorization: Bearer lzk_your_key" \
  -H "Content-Type: application/json" \
  -d '{"productIds":["prod_a","prod_b","prod_c"]}' \
  "https://api.linkz.ee/v1/uploads/video/montage"
```

| Paramètre | Où | Obligatoire | Description |
| --- | --- | --- | --- |
| `productIds` | body | Non | Jusqu’à 6 identifiants de produit, dans l’ordre d’apparition. Absent : les produits les plus récents avec photo. |

Renvoie le job de traitement (`{ id, kind, status, result, error }`), comme
l’envoi de vidéo. Erreurs : `400` quand moins de 3 produits ont une photo.
