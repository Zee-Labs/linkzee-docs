Los endpoints de contenido exponen lo que un visitante ve en la zona de enlaces de
una página: enlaces sueltos, colecciones (grupos de enlaces) e ítems de asistente
de IA, además de un bloque `meta` que resume la vitrina de productos (contadores,
chips de categoría, productos destacados y la primera página del catálogo).

Todas las solicitudes van a `https://api.linkz.ee` y deben incluir tu clave de API:

```
Authorization: Bearer lzk_your_key
```

<Note>
Los productos no forman parte del árbol reordenable. La vitrina sigue su propio
orden (los más nuevos primero, o el orden manual definido con
[`PUT /v1/products/order`](/es/api-reference/products)). Las entradas de producto
enviadas al endpoint de reordenación se ignoran.
</Note>

## Obtener el árbol de contenido

```
GET /v1/content
```

Devuelve el árbol de contenido de tu página, más un resumen `meta` de la vitrina de
productos. Es la vista del dueño: responde incluso cuando la página está oculta, y
entonces `pageHidden` es `true` (la página pública devuelve `404` en ese caso).

### Solicitud

```bash
curl -X GET \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/content
```

### Respuesta

El objeto `data` tiene tres partes: `meta` (resumen de la vitrina), `root` (la lista
ordenada de entradas de contenido, cada una un `link`, una `collection` o un
`ai_assistant`) y `pageHidden`.

activos) se quitan de `root`. Las tarjetas especiales (mapa, reseñas, servicios y
las demás) no forman parte de esta respuesta; su posición se define con el endpoint
de reordenación de abajo.

`"shake"`, `"shine"`, `"pulse"` o `"bounce"` (el resaltado animado Premium);
`cardSize` es `"normal"` o `"wide"` (una tarjeta ancha ocupa las dos columnas de la
cuadrícula); `imageRatio` es el ancho de la imagen dividido por su alto (`1` para
cuadrada); y `order` es la posición del producto, que usa el cursor del catálogo en
el orden manual.

## Reordenar el contenido

```
PUT /v1/content/order
```

Define el orden de la zona de enlaces en una sola llamada: enlaces, colecciones,
asistentes de IA y las tarjetas especiales. La posición de cada entrada en el array
se convierte en su nuevo orden. Requiere una clave con el alcance **write**. La
herramienta MCP `reorder_content` usa las mismas reglas, y `get_content_tree`
devuelve el árbol exactamente en este formato.

### Solicitud

```bash
curl -X PUT \
  -H "Authorization: Bearer lzk_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "root": [
      { "type": "link", "id": "507f1f77bcf86cd799439011" },
      { "type": "section", "key": "services" },
      {
        "type": "collection",
        "id": "507f1f77bcf86cd799439020",
        "children": [
          { "type": "link", "id": "507f1f77bcf86cd799439012" },
          { "type": "ai_assistant", "id": "507f1f77bcf86cd799439030" }
        ]
      },
      { "type": "section", "key": "reviews" },
      { "type": "section", "key": "map" }
    ]
  }' \
  https://api.linkz.ee/v1/content/order
```

### Parámetros

| Parámetro | Tipo | Obligatorio | Descripción |
| --- | --- | --- | --- |
| `root` | array | Sí | Entradas de nivel superior en su nuevo orden. Puede estar vacío. |
| `root[].type` | string | Sí | `link`, `collection`, `ai_assistant`, `section` o `product` (se ignora). |
| `root[].id` | string | Excepto para `section` | El ID de la entrada. |
| `root[].key` | string | Con `section` | La tarjeta especial: `carousel`, `map`, `tips`, `review` (reseña de Google), `reviews`, `packages`, `services`, `instagram` o `social:<network>` (por ejemplo `social:instagram`). |
| `root[].children` | array | No | Ítems hijos, en orden. Solo se usa cuando `type` es `collection`. |
| `root[].children[].type` | string | Sí | `link`, `ai_assistant` o `product` (se ignora). |
| `root[].children[].id` | string | Sí | El ID del ítem hijo. |

### Cómo aplica el servidor el árbol

- **Árbol incompleto.** Los enlaces y colecciones que omites no se pierden:
  conservan su lugar junto a sus vecinos anteriores. Los hijos de una colección
  enviada sin `children` se quedan como están. Los asistentes de IA solo se mueven
  cuando están en el árbol.
- **Tarjetas especiales.** Con al menos una `section` en el árbol, el servidor
  recalcula la posición de **todas** las tarjetas especiales de la página (las
  tarjetas que omitiste conservan su lugar relativo). Sin ninguna `section`, las
  tarjetas no se tocan.
- **Las entradas inválidas nunca hacen fallar la llamada.** Se omiten y se informan
  en `warnings`:

| Advertencia | Significado |
| --- | --- |
| `section_not_on_page:<key>` | La tarjeta no está en la página (por ejemplo, no hay dirección para el mapa). |
| `unknown_item:<id>` | No hay ningún enlace ni asistente de IA con este ID en tu tienda. |
| `unknown_collection:<id>` | No hay ninguna colección con este ID en tu tienda. |
| `media_block_not_in_collection:<id>` | Un bloque de medios no puede ir dentro de una colección; se queda en la raíz, justo después de ella. |

<Warning>
Primero se guardan los ítems y luego las posiciones de las tarjetas. En el caso poco
frecuente de una falla entre las dos escrituras, los ítems ya están en el nuevo
orden y las tarjetas conservan su posición anterior; enviar de nuevo el mismo árbol
lo corrige.
</Warning>

### Respuesta

```json
{
  "error": false,
  "message": "Content reordered successfully",
  "data": {
    "ok": true,
    "warnings": ["section_not_on_page:map"]
  }
}
```

`warnings` solo aparece cuando algo se omitió.
