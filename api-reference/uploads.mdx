Use the uploads endpoint to send an image to Linkzee and get back a permanent,
CDN-hosted URL. Every image is converted to **WebP**, resized to fit within
1600&nbsp;px, and served with long-lived caching, so the URL you receive is ready
to drop straight into a product, link, or your store profile.

The endpoint lives under the base URL `https://api.linkz.ee` and requires the
`Authorization: Bearer lzk_your_key` header. Uploading changes your storefront,
so it needs a key with the **write** scope.

## Upload an image

```
POST /v1/uploads/image
```

Uploads a single image and returns its hosted URL. Send the request as
`multipart/form-data`, not JSON.

### Request

```bash
curl -X POST \
  -H "Authorization: Bearer lzk_your_key" \
  -F "file=@/path/to/photo.jpg" \
  -F "kind=product" \
  -F "productId=507f1f77bcf86cd799439011" \
  https://api.linkz.ee/v1/uploads/image
```

### Parameters

Send these as multipart form fields.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `file` | file | Yes | The image to upload. Any common format (JPEG, PNG, WebP, etc.), up to **8&nbsp;MB**. It is converted to WebP automatically. |
| `kind` | string | No | Where the image belongs. Determines a stable storage location so re-uploading the same kind overwrites the previous image instead of piling up. See the table below. |
| `productId` | string | No | Required when `kind` is `product`. The product this image belongs to. It must be a product in your own store. |
| `linkId` | string | No | Required when `kind` is `link`, `linkMedia`, `linkPoster`, or `linkMediaSlot`. The link the image belongs to. It must be a link in your own store. |
| `slot` | string | No | Required when `kind` is `linkMediaSlot`: the photo slot (`0`–`9`) of a Before & After / Gallery block. The slot is the stable file id — re-uploading the same slot replaces the photo. |
| `staffId` | string | No | Required when `kind` is `staffAvatar`. The team member the avatar belongs to. |
| `socialKey` | string | No | Required when `kind` is `socialCard`. The social network the card cover belongs to (e.g. `instagram`, `tiktok`, `youtube`). |

#### Values for `kind`

| `kind` | Use it for | Also send |
| --- | --- | --- |
| `logo` | Your store logo | — |
| `product` | A product image | `productId` |
| `wallpaper` | Your page wallpaper | — |
| `wallpaperPoster` | Legacy — the poster for a video wallpaper is now generated automatically from the video | — |
| `banner` | Your header banner | — |
| `cutout` | A header cutout image | — |
| `link` | A link thumbnail | `linkId` |
| `linkMedia` | A link card cover | `linkId` |
| `linkPoster` | A link video poster | `linkId` |
| `linkMediaSlot` | One photo of a Before & After / Gallery block (Premium; resized to 1344px wide (fit inside 1344×2016)) | `linkId`, `slot` |
| `aiAssistantAvatar` | Your AI assistant avatar | — |
| `staffAvatar` | A team member's photo | `staffId` |
| `heroPoster` | Legacy — the poster for a hero video is now generated automatically from the video | — |
| `socialCard` | A social network card cover | `socialKey` |

<Note>
When you send a `kind` (and its matching ID), the image is stored at a fixed
location for that resource, so a new upload replaces the old one. Omit `kind`
and each upload gets its own unique URL instead.
</Note>

<Warning>
Files over 8&nbsp;MB are rejected. Only image files are accepted — other file
types return a `400 Bad Request`. If you set `kind` to `product` or `link`, the
matching `productId` or `linkId` must reference a resource in your own store.
</Warning>

### Response

The `url` is your hosted image. Because stored images are cached aggressively,
the URL ends with a `?v=` version marker that changes on every upload — always
use the exact URL you get back.

```json
{
  "error": false,
  "message": "Upload completed successfully",
  "data": {
    "url": "https://cdn.linkz.ee/u/abc/products/507f1f77bcf86cd799439011.webp?v=1721577600000",
    "width": 1200,
    "height": 1200,
    "format": "webp",
    "hasAlpha": false
  }
}
```

| Field | Type | Description |
| --- | --- | --- |
| `url` | string | The hosted, cache-busted image URL. |
| `width` | integer | Width of the processed image, in pixels. |
| `height` | integer | Height of the processed image, in pixels. |
| `format` | string | Always `webp`. |
| `hasAlpha` | boolean | Whether the image has a transparent channel. |

<Note>
To attach an uploaded image to a resource, take the returned `url` and set it on
the product or link — for example, pass it as the product's `image` when you
create or update it.
</Note>

## Video uploads (hero and wallpaper)

```
POST /v1/uploads/video?kind=hero|wallpaper
```

Uploads a short video for your **Hero** header or your page **wallpaper** and
optimizes it in the background. Send it as `multipart/form-data` with a single
`file` field (MP4 or MOV, up to **40&nbsp;MB**). This endpoint requires a key
with the **write** scope and a store on a **Premium** plan.

```bash
curl -X POST \
  -H "Authorization: Bearer lzk_your_key" \
  -F "file=@/path/to/clip.mp4" \
  "https://api.linkz.ee/v1/uploads/video?kind=hero"
```

| Parameter | In | Required | Description |
| --- | --- | --- | --- |
| `kind` | query | Yes | `hero` for the Hero header video, `wallpaper` for the page background. |
| `file` | multipart | Yes | The video to upload — MP4 or MOV, up to **40&nbsp;MB**. |

### Response

The request returns `200` as soon as the file is received, with a **job** that
describes the optimization, plus a `pollMs` hint for how often to check on it.

```json
{
  "error": false,
  "message": "Video queued for processing",
  "data": {
    "id": "66f1c2a9e4b0c1d2f3a4b5c6",
    "kind": "hero",
    "status": "queued",
    "error": "",
    "errorCode": "",
    "tries": 0,
    "result": null,
    "createdAt": "2026-10-14T12:00:00.000Z",
    "finishedAt": null,
    "pollMs": 1500
  }
}
```

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | The job id. Use it to poll for progress. |
| `kind` | string | `hero` or `wallpaper`. |
| `status` | string | `queued` → `processing` → `ready`, `failed` or `superseded`. `superseded` means a newer upload of the same kind replaced this one. |
| `error` | string \| null | A human-readable message when the job failed. |
| `errorCode` | string \| null | A stable error code when the job failed. |
| `tries` | integer | How many times the optimization was attempted. |
| `result` | object \| null | Filled in when `status` is `ready` — see below. |
| `createdAt` | string | When the job was created (ISO 8601). |
| `finishedAt` | string \| null | When the job finished, if it has. |

When the job is `ready`, `result` contains the optimized video — and it is
**already applied** to your store, so no extra `PATCH` is needed:

| Field | Type | Description |
| --- | --- | --- |
| `url` | string | The hosted, optimized video URL. |
| `posterUrl` | string | The cover image, generated from the video's first frame. |
| `durationMs` | integer | Duration of the optimized video, in milliseconds. |
| `width` | integer | Width in pixels. |
| `height` | integer | Height in pixels. |
| `bytes` | integer | Size of the optimized file. |
| `trimmed` | boolean | `true` when the original was longer than 15 seconds and was cut. |

### Polling and managing video jobs

```
GET    /v1/uploads/video/jobs/{id}
GET    /v1/uploads/video/latest?kind=hero
DELETE /v1/uploads/video/{kind}
```

- `GET /v1/uploads/video/jobs/{id}` returns the job in its current state — poll
  it every `pollMs` milliseconds until `status` is `ready` or `failed`.
- `GET /v1/uploads/video/latest?kind=hero` (or `kind=wallpaper`) returns the
  most recent job for that kind, or `null` if there has never been one.
- `DELETE /v1/uploads/video/{kind}` removes the published video (`hero` or
  `wallpaper`) from your page.

### Output profile

Every video is encoded to the same profile so it starts instantly on mobile:

| Setting | Value |
| --- | --- |
| Resolution | **720p** on the short side — never upscaled |
| Frame rate | 24 fps |
| Codec | H.264 (MP4) |
| Length | The **first 15 seconds** |
| Audio | Removed — videos are always silent |
| Size | Usually **≤ ~3&nbsp;MB** |

<Note>
Videos longer than 15 seconds are never rejected for their length — they are
trimmed, and the result reports `trimmed: true`. An upload is rejected only when
the file is over 40&nbsp;MB or isn't a valid video file.
</Note>

<Note>
`POST /v1/uploads/video` with `kind=link` (a link's video) still stores the raw
file as before — this optimization is not applied.
</Note>

## Generate a hero video from product photos

```
POST /v1/uploads/video/montage
```

Builds a short cinematic montage from your product photos (slow zooms and
pans, dissolves, about 14 seconds) and queues it as a **hero** video — the same
job and polling as an upload, applied to the hero when ready. Uses the newest
products that have a photo, or the ones you pass in `productIds` (up to 6, in
order). Requires a **write** key and a **Premium** store; at least 3 products
with a photo hosted on Linkzee.

```bash
curl -X POST \
  -H "Authorization: Bearer lzk_your_key" \
  -H "Content-Type: application/json" \
  -d '{"productIds":["prod_a","prod_b","prod_c"]}' \
  "https://api.linkz.ee/v1/uploads/video/montage"
```

| Parameter | Where | Required | Description |
| --- | --- | --- | --- |
| `productIds` | body | No | Up to 6 product ids, in the order they should appear. Omitted: the newest products with a photo. |

Returns the processing job (`{ id, kind, status, result, error }`), exactly like
the video upload. Errors: `400` when fewer than 3 products have a photo.
