Use o endpoint de uploads para enviar uma imagem ao Linkzee e receber de volta uma
URL permanente, hospedada em CDN. Toda imagem é convertida para **WebP**,
redimensionada para caber dentro de 1600&nbsp;px e servida com cache de longa
duração, então a URL que você recebe já está pronta para usar direto em um
produto, link ou no perfil da sua loja.

O endpoint fica sob a URL base `https://api.linkz.ee` e exige o cabeçalho
`Authorization: Bearer lzk_your_key`. Fazer upload altera sua página, então é
preciso uma chave com o escopo **write**.

## Enviar uma imagem

```
POST /v1/uploads/image
```

Envia uma única imagem e retorna sua URL hospedada. Envie a requisição como
`multipart/form-data`, não como JSON.

### Requisição

```bash
curl -X POST \
  -H "Authorization: Bearer lzk_your_key" \
  -F "file=@/path/to/photo.jpg" \
  -F "kind=product" \
  -F "productId=507f1f77bcf86cd799439011" \
  https://api.linkz.ee/v1/uploads/image
```

### Parâmetros

Envie-os como campos de formulário multipart.

| Parâmetro | Tipo | Obrigatório | Descrição |
| --- | --- | --- | --- |
| `file` | file | Sim | A imagem a enviar. Qualquer formato comum (JPEG, PNG, WebP, etc.), até **8&nbsp;MB**. É convertida para WebP automaticamente. |
| `kind` | string | Não | Onde a imagem se encaixa. Determina um local de armazenamento estável, de modo que reenviar o mesmo tipo sobrescreve a imagem anterior em vez de acumular. Veja a tabela abaixo. |
| `productId` | string | Não | Obrigatório quando `kind` é `product`. O produto ao qual esta imagem pertence. Deve ser um produto da sua própria loja. |
| `linkId` | string | Não | Obrigatório quando `kind` é `link`, `linkMedia` ou `linkPoster`. O link ao qual a imagem pertence. Deve ser um link da sua própria loja. |
| `staffId` | string | Não | Obrigatório quando `kind` é `staffAvatar`. O membro da equipe ao qual o avatar pertence. |
| `socialKey` | string | Não | Obrigatório quando `kind` é `socialCard`. A rede social à qual a capa do card pertence (ex.: `instagram`, `tiktok`, `youtube`). |

#### Valores para `kind`

| `kind` | Use para | Envie também |
| --- | --- | --- |
| `logo` | O logo da sua loja | — |
| `product` | A imagem de um produto | `productId` |
| `wallpaper` | O papel de parede da sua página | — |
| `wallpaperPoster` | Legado — o pôster de um papel de parede em vídeo agora é gerado automaticamente a partir do vídeo | — |
| `banner` | O banner do seu cabeçalho | — |
| `cutout` | Uma imagem recortada do cabeçalho | — |
| `link` | A miniatura de um link | `linkId` |
| `linkMedia` | A capa do card de um link | `linkId` |
| `linkPoster` | O pôster de vídeo de um link | `linkId` |
| `aiAssistantAvatar` | O avatar do seu assistente de IA | — |
| `staffAvatar` | A foto de um membro da equipe | `staffId` |
| `heroPoster` | Legado — o pôster de um vídeo da hero agora é gerado automaticamente a partir do vídeo | — |
| `socialCard` | A capa do card de uma rede social | `socialKey` |

<Note>
Quando você envia um `kind` (e seu ID correspondente), a imagem é armazenada em um
local fixo para aquele recurso, de modo que um novo upload substitui o antigo.
Omita o `kind` e cada upload recebe sua própria URL exclusiva.
</Note>

<Warning>
Arquivos acima de 8&nbsp;MB são rejeitados. Apenas arquivos de imagem são aceitos —
outros tipos de arquivo retornam um `400 Bad Request`. Se você definir `kind` como
`product` ou `link`, o `productId` ou `linkId` correspondente deve referenciar um
recurso da sua própria loja.
</Warning>

### Resposta

A `url` é sua imagem hospedada. Como as imagens armazenadas são fortemente
cacheadas, a URL termina com um marcador de versão `?v=` que muda a cada upload —
use sempre a URL exata que você recebe de volta.

```json
{
  "error": false,
  "message": "Upload completed successfully",
  "data": {
    "url": "https://cdn.linkz.ee/u/abc/products/507f1f77bcf86cd799439011.webp?v=1721577600000",
    "width": 1200,
    "height": 1200,
    "format": "webp",
    "hasAlpha": false
  }
}
```

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `url` | string | A URL hospedada da imagem, com cache-busting. |
| `width` | integer | Largura da imagem processada, em pixels. |
| `height` | integer | Altura da imagem processada, em pixels. |
| `format` | string | Sempre `webp`. |
| `hasAlpha` | boolean | Se a imagem tem canal transparente. |

<Note>
Para anexar uma imagem enviada a um recurso, pegue a `url` retornada e defina-a no
produto ou link — por exemplo, passe-a como o `image` do produto ao criá-lo ou
atualizá-lo.
</Note>

## Upload de vídeo (hero e papel de parede)

```
POST /v1/uploads/video?kind=hero|wallpaper
```

Envia um vídeo curto para o topo **Hero** ou para o **papel de parede** da sua
página e o otimiza em segundo plano. Envie como `multipart/form-data` com um
único campo `file` (MP4 ou MOV, até **40&nbsp;MB**). Este endpoint exige uma
chave com o escopo **write** e uma loja em um plano **Premium**.

```bash
curl -X POST \
  -H "Authorization: Bearer lzk_your_key" \
  -F "file=@/path/to/clip.mp4" \
  "https://api.linkz.ee/v1/uploads/video?kind=hero"
```

| Parâmetro | Onde | Obrigatório | Descrição |
| --- | --- | --- | --- |
| `kind` | query | Sim | `hero` para o vídeo do topo Hero, `wallpaper` para o fundo da página. |
| `file` | multipart | Sim | O vídeo a enviar — MP4 ou MOV, até **40&nbsp;MB**. |

### Resposta

A requisição retorna `200` assim que o arquivo é recebido, com um **job** que
descreve a otimização, mais uma dica `pollMs` de com que frequência consultá-lo.

```json
{
  "error": false,
  "message": "Video queued for processing",
  "data": {
    "id": "66f1c2a9e4b0c1d2f3a4b5c6",
    "kind": "hero",
    "status": "queued",
    "error": "",
    "errorCode": "",
    "tries": 0,
    "result": null,
    "createdAt": "2026-10-14T12:00:00.000Z",
    "finishedAt": null,
    "pollMs": 1500
  }
}
```

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `id` | string | O ID do job. Use-o para acompanhar o progresso. |
| `kind` | string | `hero` ou `wallpaper`. |
| `status` | string | `queued` → `processing` → `ready`, `failed` ou `superseded`. `superseded` significa que um upload mais novo do mesmo tipo substituiu este. |
| `error` | string \| null | Uma mensagem legível quando o job falhou. |
| `errorCode` | string \| null | Um código de erro estável quando o job falhou. |
| `tries` | integer | Quantas vezes a otimização foi tentada. |
| `result` | object \| null | Preenchido quando `status` é `ready` — veja abaixo. |
| `createdAt` | string | Quando o job foi criado (ISO 8601). |
| `finishedAt` | string \| null | Quando o job terminou, se já terminou. |

Quando o job está `ready`, `result` contém o vídeo otimizado — e ele **já está
aplicado** à sua loja, então não é preciso nenhum `PATCH` extra:

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `url` | string | A URL hospedada do vídeo otimizado. |
| `posterUrl` | string | A imagem de capa, gerada a partir do primeiro quadro do vídeo. |
| `durationMs` | integer | Duração do vídeo otimizado, em milissegundos. |
| `width` | integer | Largura em pixels. |
| `height` | integer | Altura em pixels. |
| `bytes` | integer | Tamanho do arquivo otimizado. |
| `trimmed` | boolean | `true` quando o original tinha mais de 15 segundos e foi cortado. |

### Consultar e gerenciar jobs de vídeo

```
GET    /v1/uploads/video/jobs/{id}
GET    /v1/uploads/video/latest?kind=hero
DELETE /v1/uploads/video/{kind}
```

- `GET /v1/uploads/video/jobs/{id}` retorna o job no estado atual — consulte a
  cada `pollMs` milissegundos até o `status` ser `ready` ou `failed`.
- `GET /v1/uploads/video/latest?kind=hero` (ou `kind=wallpaper`) retorna o job
  mais recente daquele tipo, ou `null` se nunca houve um.
- `DELETE /v1/uploads/video/{kind}` remove o vídeo publicado (`hero` ou
  `wallpaper`) da sua página.

### Perfil de saída

Todo vídeo é codificado no mesmo perfil, para começar na hora no celular:

| Ajuste | Valor |
| --- | --- |
| Resolução | **720p** no lado menor — nunca ampliado |
| Taxa de quadros | 24 fps |
| Codec | H.264 (MP4) |
| Duração | Os **primeiros 15 segundos** |
| Áudio | Removido — os vídeos são sempre sem som |
| Tamanho | Geralmente **≤ ~3&nbsp;MB** |

<Note>
Vídeos com mais de 15 segundos nunca são rejeitados pela duração — são cortados,
e o resultado informa `trimmed: true`. Um upload só é rejeitado quando o arquivo
passa de 40&nbsp;MB ou não é um arquivo de vídeo válido.
</Note>

<Note>
`POST /v1/uploads/video` com `kind=link` (o vídeo de um link) continua
armazenando o arquivo original como antes — essa otimização não é aplicada.
</Note>
