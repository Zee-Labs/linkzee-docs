Os endpoints de conteúdo expõem o que um visitante vê na zona de links de uma
página: links avulsos, coleções (grupos de links) e itens de assistente de IA,
além de um bloco `meta` que resume a vitrine de produtos (contadores, chips de
categoria, produtos em destaque e a primeira página do catálogo).

Todas as requisições vão para `https://api.linkz.ee` e devem incluir sua chave de API:

```
Authorization: Bearer lzk_your_key
```

<Note>
Os produtos não fazem parte da árvore reordenável. A vitrine segue a própria
ordem (mais novos primeiro, ou a ordem manual definida com
[`PUT /v1/products/order`](/pt-BR/api-reference/products)). Entradas de produto
enviadas ao endpoint de reordenação são ignoradas.
</Note>

## Obter a árvore de conteúdo

```
GET /v1/content
```

Retorna a árvore de conteúdo da sua página, mais um resumo `meta` da vitrine de
produtos. É a visão do dono: responde mesmo quando a página está oculta, e então
`pageHidden` é `true` (a página pública retorna `404` nesse caso).

### Requisição

```bash
curl -X GET \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/content
```

### Resposta

O objeto `data` tem três partes: `meta` (resumo da vitrine), `root` (a lista
ordenada de entradas de conteúdo, cada uma um `link`, uma `collection` ou um
`ai_assistant`) e `pageHidden`.

ativos) são removidas de `root`. Os cards especiais (mapa, avaliações, serviços e

endpoint de reordenação abaixo.
</Note>

`"shake"`, `"shine"`, `"pulse"` ou `"bounce"` (o destaque animado Premium);
`cardSize` é `"normal"` ou `"wide"` (um card largo ocupa as duas colunas da
grade); `imageRatio` é a largura da imagem dividida pela altura (`1` para
quadrada); e `order` é a posição do produto, usada pelo cursor do catálogo na
ordem manual.

## Reordenar o conteúdo

```
PUT /v1/content/order
```

Define a ordem da zona de links em uma chamada: links, coleções, assistentes de
IA e os cards especiais. A posição de cada entrada no array vira a nova ordem
dela. Exige uma chave com o escopo **write**. A ferramenta MCP `reorder_content`
usa as mesmas regras, e `get_content_tree` retorna a árvore exatamente neste
formato.

### Requisição

```bash
curl -X PUT \
  -H "Authorization: Bearer lzk_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "root": [
      { "type": "link", "id": "507f1f77bcf86cd799439011" },
      { "type": "section", "key": "services" },
      {
        "type": "collection",
        "id": "507f1f77bcf86cd799439020",
        "children": [
          { "type": "link", "id": "507f1f77bcf86cd799439012" },
          { "type": "ai_assistant", "id": "507f1f77bcf86cd799439030" }
        ]
      },
      { "type": "section", "key": "reviews" },
      { "type": "section", "key": "map" }
    ]
  }' \
  https://api.linkz.ee/v1/content/order
```

### Parâmetros

| Parâmetro | Tipo | Obrigatório | Descrição |
| --- | --- | --- | --- |
| `root` | array | Sim | Entradas de nível superior na nova ordem. Pode ser vazio. |
| `root[].type` | string | Sim | `link`, `collection`, `ai_assistant`, `section` ou `product` (ignorado). |
| `root[].id` | string | Exceto para `section` | O ID da entrada. |
| `root[].key` | string | Com `section` | O card especial: `carousel`, `map`, `tips`, `review` (avaliação do Google), `reviews`, `packages`, `services`, `instagram` ou `social:<network>` (por exemplo `social:instagram`). |
| `root[].children` | array | Não | Itens filhos, em ordem. Usado só quando `type` é `collection`. |
| `root[].children[].type` | string | Sim | `link`, `ai_assistant` ou `product` (ignorado). |
| `root[].children[].id` | string | Sim | O ID do item filho. |

### Como o servidor aplica a árvore

- **Árvore incompleta.** Links e coleções que você deixa de fora não se perdem:
  eles mantêm o lugar ao lado dos antigos vizinhos. Os filhos de uma coleção
  enviada sem `children` ficam como estão. Os assistentes de IA só mudam de
  lugar quando estão na árvore.
- **Cards especiais.** Com pelo menos uma `section` na árvore, o servidor
  recalcula a posição de **todos** os cards especiais da página (os cards que
  você deixou de fora mantêm o lugar relativo). Sem nenhuma `section`, os cards
  não são mexidos.
- **Entradas inválidas nunca derrubam a chamada.** Elas são ignoradas e
  informadas em `warnings`:

| Aviso | Significado |
| --- | --- |
| `section_not_on_page:<key>` | O card não está na página (por exemplo, sem endereço de mapa). |
| `unknown_item:<id>` | Nenhum link ou assistente de IA com este ID na sua loja. |
| `unknown_collection:<id>` | Nenhuma coleção com este ID na sua loja. |
| `media_block_not_in_collection:<id>` | Um bloco de mídia não pode ficar dentro de uma coleção; ele fica na raiz, logo depois dela. |

<Warning>
Os itens são salvos primeiro, depois as posições dos cards. No caso raro de uma
falha entre as duas escritas, os itens já estão na nova ordem e os cards mantêm
a posição anterior; enviar a mesma árvore de novo corrige.
</Warning>

### Resposta

```json
{
  "error": false,
  "message": "Content reordered successfully",
  "data": {
    "ok": true,
    "warnings": ["section_not_on_page:map"]
  }
}
```

`warnings` só aparece quando algo foi ignorado.
