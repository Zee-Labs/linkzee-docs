Mit den Kalender-Endpunkten steuern Sie Ihren Buchungskalender programmatisch:
Legen Sie die **Leistungen** fest, die Menschen buchen können, Ihr **Team**, die
**Sperrungen** für Ihre freien Zeiten, lesen Sie die echte **Verfügbarkeit**,
um **Termine** zu erstellen und zu verwalten, moderieren Sie die **Bewertungen**,
die Sie erhalten, und verwalten Sie die **Warteliste**.

Alle Pfade liegen unter `https://api.linkz.ee/v1/agenda`. Jede Anfrage benötigt
den Header `Authorization: Bearer lzk_your_key`, und Schreiboperationen
(POST/PATCH/DELETE) erfordern einen Schlüssel mit dem **write**-Scope.

<Note>
Lesevorgänge (`GET`) funktionieren mit jedem gültigen Schlüssel. Das Erstellen,
Aktualisieren, Ändern des Status, Verschieben oder Löschen erfordert den
**write**-Scope.
</Note>

## Leistungen

Eine Leistung (ein Angebot) ist etwas, das Menschen buchen können — ein
Haarschnitt, eine Beratung, ein Gespräch. Jede Leistung hat eine Dauer und
optional einen Preis.

### Leistungen auflisten

```
GET /v1/agenda/offerings
```

Gibt jede Leistung in Ihrem Kalender in Anzeigereihenfolge zurück.

#### Anfrage

```bash
curl -X GET \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/agenda/offerings
```

#### Antwort

```json
{
  "error": false,
  "message": "Services retrieved successfully",
  "data": [
    {
      "_id": "665f0a1b2c3d4e5f60718293",
      "name": "Strategy call",
      "durationMin": 45,
      "price": 150,
      "description": "A focused 45-minute planning session.",
      "color": "#2f80ed",
      "bufferAfterMin": 15,
      "meetEnabled": true,
      "order": 0,
      "isActive": true
    }
  ]
}
```

### Leistung anlegen

```
POST /v1/agenda/offerings
```

Fügt eine neue buchbare Leistung hinzu.

#### Anfrage

```bash
curl -X POST \
  -H "Authorization: Bearer lzk_your_key" \
  -H "Content-Type: application/json" \
  -d '{"name":"Strategy call","durationMin":45,"price":150,"meetEnabled":true}' \
  https://api.linkz.ee/v1/agenda/offerings
```

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
| --- | --- | --- | --- |
| `name` | string | Ja | Name der Leistung (max. 80 Zeichen). |
| `durationMin` | integer | Ja | Dauer in Minuten (5–720). |
| `price` | number | Nein | Preis in R$. Weglassen oder `null` senden für kostenlos. |
| `description` | string | Nein | Kurze Beschreibung (max. 300 Zeichen). |
| `color` | string | Nein | Hex-Farbe für den Kalender, z. B. `#2f80ed`. |
| `bufferAfterMin` | integer | Nein | Pause in Minuten nach jeder Buchung (0–240). |
| `meetEnabled` | boolean | Nein | Erstellt einen Google-Meet-Link für jede Buchung. |
| `isActive` | boolean | Nein | Ob die Leistung buchbar ist. Standardwert ist `true`. |
| `kind` | string | Nein | `single` (Standard) oder `combo`. Ein Combo bündelt mehrere Einzelleistungen zu einem buchbaren Paket. |
| `comboItemIds` | array of string | Nein | Erforderlich, wenn `kind` `combo` ist: die IDs von 2–6 Einzelleistungen, die im Combo enthalten sind. |
| `chargeMode` | string | Nein | Online-Bezahlung: `none` (Standard, Zahlung vor Ort), `deposit` (Teilbetrag im Voraus) oder `full` (voller Preis im Voraus — erfordert einen `price` größer als 0). |
| `chargeDepositType` | string | Nein | Wie die Anzahlung berechnet wird, wenn `chargeMode` `deposit` ist: `percent` oder `fixed`. |
| `chargeDepositValue` | number | Nein | Die Höhe der Anzahlung: ein Prozentsatz von 1 bis 100, wenn `chargeDepositType` `percent` ist, oder ein fester Betrag in der Währung Ihres Stores, wenn er `fixed` ist. |

#### Antwort

```json
{
  "error": false,
  "message": "Service created successfully",
  "data": {
    "_id": "665f0a1b2c3d4e5f60718293",
    "name": "Strategy call",
    "durationMin": 45,
    "price": 150,
    "bufferAfterMin": 0,
    "meetEnabled": true,
    "order": 0,
    "isActive": true
  }
}
```

### Leistung aktualisieren

```
PATCH /v1/agenda/offerings/{id}
```

Aktualisiert eine Leistung. Senden Sie den vollständigen Satz an Feldern, genau
wie beim Erstellen.

#### Anfrage

```bash
curl -X PATCH \
  -H "Authorization: Bearer lzk_your_key" \
  -H "Content-Type: application/json" \
  -d '{"name":"Strategy call","durationMin":60,"price":180}' \
  https://api.linkz.ee/v1/agenda/offerings/665f0a1b2c3d4e5f60718293
```

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
| --- | --- | --- | --- |
| `id` | string | Ja | Die Leistungs-ID (im Pfad). |

Der Body akzeptiert dieselben Felder wie [Leistung anlegen](#create-a-service).

#### Antwort

```json
{
  "error": false,
  "message": "Service updated successfully",
  "data": {
    "_id": "665f0a1b2c3d4e5f60718293",
    "name": "Strategy call",
    "durationMin": 60,
    "price": 180,
    "isActive": true
  }
}
```

### Leistung löschen

```
DELETE /v1/agenda/offerings/{id}
```

Entfernt eine Leistung. Sie ist nicht mehr buchbar; bestehende Termine bleiben unberührt.

#### Anfrage

```bash
curl -X DELETE \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/agenda/offerings/665f0a1b2c3d4e5f60718293
```

#### Antwort

```json
{
  "error": false,
  "message": "Service deleted successfully",
  "data": { "id": "665f0a1b2c3d4e5f60718293" }
}
```

## Sperrungen

Eine Sperrung ist ein Zeitraum, in dem Sie (oder ein Teammitglied) nicht
verfügbar sind — ein Feiertag, Urlaub oder ein freier Tag. Buchungen können nicht
innerhalb einer Sperrung liegen.

<Note>
Sperrungen haben keinen Aktualisierungs-Endpunkt. Um eine zu ändern, löschen Sie
sie und legen Sie eine neue an.
</Note>

### Sperrungen auflisten

```
GET /v1/agenda/blocks
```

#### Anfrage

```bash
curl -X GET \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/agenda/blocks
```

#### Antwort

```json
      "startDate": "2026-12-24",
      "endDate": "2026-12-26",
      "allDay": true,
      "reason": "Holidays"
    }
  ]
}
```

```bash
  -d '{"startDate":"2026-12-24","endDate":"2026-12-26","allDay":true,"reason":"Holidays"}' \
```

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
| --- | --- | --- | --- |

## Verfügbarkeit

```
GET /v1/agenda/availability
```

Gibt die tatsächlich offenen Tage und Zeitfenster für eine Leistung über einen
Datumsbereich zurück — dieselbe Engine, die Ihre öffentliche Buchungsseite
antreibt, sodass sie Arbeitszeiten, bestehende Termine und Sperrungen bereits
berücksichtigt.

#### Anfrage

```bash
curl -X GET \
  -H "Authorization: Bearer lzk_your_key" \
  "https://api.linkz.ee/v1/agenda/availability?offeringId=665f0a1b2c3d4e5f60718293&from=2026-07-21&to=2026-07-25&detail=slots"
```

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
| --- | --- | --- | --- |
| `offeringId` | string | Ja | Die zu prüfende Leistung. |
| `from` | string | Ja | Startdatum, `YYYY-MM-DD` (in der Zeitzone Ihres Kalenders). |
| `to` | string | Ja | Enddatum, `YYYY-MM-DD`. |
| `staffId` | string | Nein | Beschränkt die Verfügbarkeit auf ein Teammitglied (Team-Modus). |
| `extraOfferingIds` | string | Nein | Durch Kommas getrennte IDs von bis zu 4 zusätzlichen Leistungen, die zusammen mit der Hauptleistung gebucht werden (ein Warenkorb). Die Verfügbarkeit berücksichtigt dann die kombinierte Dauer. |
| `detail` | string | Nein | `days` (Standard) gibt nur den Zustand pro Tag zurück; `slots` gibt zusätzlich die buchbaren Startzeiten zurück. |

#### Antwort

```json
{
  "error": false,
  "message": "Availability retrieved successfully",
  "data": {
    "days": [
      { "date": "2026-07-21", "state": "free", "density": "low" },
      { "date": "2026-07-22", "state": "full", "density": "high" },
      { "date": "2026-07-23", "state": "closed", "density": "none" }
    ],
    "slots": [
      { "startAt": "2026-07-21T12:00:00.000Z" },
      { "startAt": "2026-07-21T12:45:00.000Z" }
    ],
    "charge": {
      "mode": "deposit",
      "amountDueCents": 5000,
      "totalCents": 15000,
      "currency": "brl"
    },
    "stepMin": 15,
    "timezone": "America/Sao_Paulo"
  }
}
```

Der `state` jedes Tages ist `free` (hat offene Zeitfenster), `full` (vollständig
ausgebucht) oder `closed` (kein Arbeitstag); `density` (`none`, `low`, `medium`,
`high`) sagt Ihnen, wie ausgelastet der Tag bereits ist. Zeiten werden in UTC
(`Z`) zurückgegeben.

Wenn für die Leistung eine Online-Bezahlung konfiguriert ist, beschreibt
`charge`, was der Besucher bei der Buchung zahlt: `mode` (`none`, `deposit` oder
`full`), `amountDueCents` (der bei der Buchung fällige Betrag, in Cent),
`totalCents` (der volle Preis der Leistung, in Cent) und `currency`. Ohne
eingerichtete Bezahlung ist `mode` `none` und die Beträge sind `0`.

<Warning>
Das Verbinden eines Google Calendar erfolgt über einen Anmeldevorgang im

nur den Status lesen und die Verbindung trennen.
</Warning>

## Bewertungen

Nach einem abgeschlossenen Termin können Besucher eine Bewertung hinterlassen.
Bewertungen werden **niemals bearbeitet oder gelöscht** — die einzige
Moderationsaktion ist, eine Bewertung auf Ihrer öffentlichen Seite auszublenden
(für Sie bleibt sie sichtbar, und Sie können sie jederzeit wieder einblenden).

### Bewertungen auflisten

```
GET /v1/agenda/reviews
```

Gibt jede Bewertung zurück, die Ihr Kalender erhalten hat, **einschließlich der
ausgeblendeten**, neueste zuerst.

#### Anfrage

```bash
curl -X GET \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/agenda/reviews
```

#### Antwort

```json
{
  "error": false,
  "message": "Reviews retrieved successfully",
  "data": [
    {
      "id": "665f33aa11bb22cc33dd44ee",
      "rating": 5,
      "comment": "Great service, highly recommend!",
      "visitorName": "João Lima",
      "visitorPhone": "+5511999998888",
      "visitorEmail": "joao@example.com",
      "offeringId": "665e11bb22cc33dd44ee55ff",
      "offeringName": "Haircut",
      "staffId": null,
      "appointmentAt": "2026-07-22T14:00:00.000Z",
      "hidden": false,
      "featured": false,
      "followedUpAt": null,
      "createdAt": "2026-07-22T18:30:00.000Z"
    }
  ]
}
```

#### Felder

| Feld | Beschreibung |
| --- | --- |
| `rating` | 1 bis 5 Sterne. |
| `comment` | Was der Kunde geschrieben hat. Nie bearbeitbar. |
| `visitorName` / `visitorPhone` / `visitorEmail` | Der Kunde, der gebucht hat, damit Sie nachfassen können. Dieselben Daten wie beim Termin. |
| `offeringId` / `offeringName` | Die bewertete Leistung. |
| `staffId` | Die Fachkraft, die den Termin übernommen hat, wenn Sie ein Team haben. |
| `appointmentAt` | Wann der Termin stattgefunden hat (ISO 8601, UTC). |
| `hidden` | `true` bedeutet, dass sie nicht in Ihren öffentlichen Durchschnitt einfließt. |
| `featured` | `true` bedeutet, dass sie im Bewertungsblock auf Ihrer Seite zuerst erscheint. |
| `followedUpAt` | Wann Sie die Bewertung als bearbeitet markiert haben, oder `null`. |

<Note>
  `visitorPhone` und `visitorEmail` sind die Kontaktdaten Ihres Kunden —
  dieselben, die auch der Termine-Endpunkt liefert. Behandeln Sie die Antwort
  als personenbezogene Daten und halten Sie Ihren API-Schlüssel privat.
</Note>

### Bewertung aus- oder einblenden

```
PATCH /v1/agenda/reviews/{id}
```

Schaltet die Sichtbarkeit einer Bewertung auf Ihrer öffentlichen Seite um.
Erfordert den **write**-Scope.

Bewertungen werden über die API nie bearbeitet oder gelöscht — Ausblenden ist
die einzige hier verfügbare Moderationsaktion. Eine Bewertung hervorzuheben
oder als bearbeitet zu markieren geschieht in Ihrem Dashboard.

#### Anfrage

```bash
curl -X PATCH \
  -H "Authorization: Bearer lzk_your_key" \
  -H "Content-Type: application/json" \
  -d '{"hidden":true}' \
  https://api.linkz.ee/v1/agenda/reviews/665f33aa11bb22cc33dd44ee
```

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
| --- | --- | --- | --- |
| `id` | string | Ja | Die Bewertungs-ID (im Pfad). |
| `hidden` | boolean | Ja | `true` blendet die Bewertung auf der öffentlichen Seite aus; `false` zeigt sie wieder an. |

#### Antwort

```json
{
  "error": false,
  "message": "Review updated successfully",
  "data": { "id": "665f33aa11bb22cc33dd44ee", "hidden": true }
}
```

<Note>
Es gibt keinen Endpunkt zum Bearbeiten oder Löschen einer Bewertung — das
Ausblenden ist die einzige Moderationsaktion, damit die Bewertungen
vertrauenswürdig bleiben.
</Note>

## Warteliste

Wenn ein Zeitraum keine freien Zeitfenster hat, können sich Besucher auf die
Warteliste setzen. Sobald ein passendes Zeitfenster frei wird, bietet das System
es automatisch dem ersten kompatiblen Eintrag an.

### Warteliste auflisten

```
GET /v1/agenda/waitlist
```

Gibt die aktuelle Warteschlange der Besucher zurück, die auf ein Zeitfenster warten.

#### Anfrage

```bash
curl -X GET \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/agenda/waitlist
```

#### Antwort

```json
{
  "error": false,
  "message": "Waitlist retrieved successfully",
  "data": [
    {
      "id": "665f44bb55cc66dd77ee88ff",
      "position": 1,
      "name": "Maria Alves",
      "phone": "+5511988887777",
      "dateFrom": "2026-07-21",
      "dateTo": "2026-07-25",
      "periods": ["morning", "afternoon"],
      "status": "waiting",
      "offeringId": "665f0a1b2c3d4e5f60718293",
      "createdAt": "2026-07-19T10:12:00.000Z"
    }
  ]
}
```

Die Einträge sind nach Eingang geordnet (`position` beginnt bei 1). `periods`
listet die bevorzugten Tagesabschnitte des Besuchers auf (`morning`,
`afternoon`, `evening`); `status` ist `waiting` oder `offered` (ein Zeitfenster
wurde angeboten und wartet auf eine Antwort).

### Wartelisten-Eintrag entfernen

```
DELETE /v1/agenda/waitlist/{id}
```

Entfernt einen Eintrag aus der Warteschlange. Erfordert den **write**-Scope.

#### Anfrage

```bash
curl -X DELETE \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/agenda/waitlist/665f44bb55cc66dd77ee88ff
```

#### Antwort

```json
{ "error": false, "message": "Waitlist entry removed", "data": { "id": "665f44bb55cc66dd77ee88ff" } }
```
