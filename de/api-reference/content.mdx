Die Inhalts-Endpunkte legen alles offen, was ein Besucher in der Link-Zone einer
Seite sieht — lose Links, Sammlungen (Gruppen von Links) und KI-Assistent-Elemente —
sowie einen `meta`-Block, der die Produktvitrine zusammenfasst (Zähler,
Kategorie-Chips, hervorgehobene Produkte und die erste Katalogseite).

Alle Anfragen gehen an `https://api.linkz.ee` und müssen deinen API-Schlüssel enthalten:

```
Authorization: Bearer lzk_your_key
```

<Note>
Produkte sind nicht Teil des neu anordenbaren Baums. Die Vitrine wird automatisch
sortiert (neueste zuerst), sodass das Neuanordnen nur Links, Sammlungen und
KI-Assistent-Elemente betrifft. An den Reorder-Endpunkt gesendete Produkteinträge
werden ignoriert.
</Note>

## Inhaltsbaum abrufen

```
GET /v1/content
```

Gibt den öffentlichen Inhaltsbaum deiner Seite zurück, dazu eine `meta`-Zusammenfassung
der Produktvitrine.

### Anfrage

```bash
curl -X GET \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/content
```

### Antwort

Das `data`-Objekt hat zwei Teile: `meta` (Vitrinen-Zusammenfassung) und `root` (die
geordnete Liste der Inhaltseinträge). Jeder `root`-Eintrag ist entweder `link`,

## Inhalt neu anordnen

```
PUT /v1/content/order
```

Legt die Reihenfolge der gesamten Link-Zone in einem einzigen Aufruf fest. Sende den
vollständigen Baum in der gewünschten Reihenfolge — die Position jedes Eintrags im
Array wird zu seiner neuen Reihenfolge. Erfordert einen Schlüssel mit dem
**write**-Scope.

### Anfrage

```bash
curl -X PUT \
  -H "Authorization: Bearer lzk_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "root": [
      { "type": "link", "id": "507f1f77bcf86cd799439011" },
      {
        "type": "collection",
        "id": "507f1f77bcf86cd799439020",
        "children": [
          { "type": "link", "id": "507f1f77bcf86cd799439012" },
          { "type": "concierge", "id": "507f1f77bcf86cd799439030" }
        ]
      }
    ]
  }' \
  https://api.linkz.ee/v1/content/order
```

### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
| --- | --- | --- | --- |
| `root` | array | Ja | Einträge der obersten Ebene in ihrer neuen Reihenfolge. Darf leer sein. |
| `root[].type` | string | Ja | Einer von `link`, `collection`, `concierge` oder `product`. |
| `root[].id` | string | Ja | Die ID des Eintrags. |
| `root[].children` | array | Nein | Untergeordnete Elemente, in Reihenfolge. Nur verwendet, wenn `type` gleich `collection` ist. |
| `root[].children[].type` | string | Ja | Einer von `link`, `concierge` oder `product`. |
| `root[].children[].id` | string | Ja | Die ID des untergeordneten Elements. |

<Warning>
Produkteinträge (auf der Wurzelebene oder innerhalb einer Sammlung) werden akzeptiert,
aber ignoriert — die Vitrine ordnet sich selbst. Sende nur `link`-, `collection`- und
`concierge`-Einträge, um das zu ändern, was tatsächlich neu angeordnet wird. Unbekannte
IDs werden stillschweigend übersprungen.
</Warning>

### Antwort

```json
{
  "error": false,
  "message": "Conteúdo reordenado com sucesso",
  "data": { "ok": true }
}
```
