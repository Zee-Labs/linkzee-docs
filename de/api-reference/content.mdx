Die Inhalts-Endpunkte legen offen, was ein Besucher im Linkbereich einer Seite
sieht: lose Links, Sammlungen (Gruppen von Links) und KI-Assistent-Elemente,
dazu einen `meta`-Block, der das Produkt-Schaufenster zusammenfasst (Zähler,
Kategorie-Chips, hervorgehobene Produkte und die erste Seite des Katalogs).

Alle Anfragen gehen an `https://api.linkz.ee` und müssen deinen API-Schlüssel
enthalten:

```
Authorization: Bearer lzk_your_key
```

<Note>
Produkte sind nicht Teil des neu anordenbaren Baums. Das Schaufenster folgt
seiner eigenen Reihenfolge (neueste zuerst oder die manuelle Reihenfolge, die
mit [`PUT /v1/products/order`](/de/api-reference/products) festgelegt wird). An
den Endpunkt zum Neuordnen gesendete Produkteinträge werden ignoriert.
</Note>

## Inhaltsbaum abrufen

```
GET /v1/content
```

Gibt den Inhaltsbaum deiner Seite zurück, dazu eine `meta`-Zusammenfassung des
Produkt-Schaufensters. Es ist die Inhaberansicht: Sie antwortet auch, wenn die
Seite ausgeblendet ist, und dann ist `pageHidden` gleich `true` (die öffentliche
Seite gibt in diesem Fall `404` zurück).

### Anfrage

```bash
curl -X GET \
  -H "Authorization: Bearer lzk_your_key" \
  https://api.linkz.ee/v1/content
```

### Antwort

Das `data`-Objekt hat drei Teile: `meta` (Zusammenfassung des Schaufensters),
`root` (die geordnete Liste der Inhaltseinträge, jeder davon ein `link`, eine

`featured`, `categories` und `catalog.items` kommen leer zurück. Leere
Sammlungen (ohne aktive untergeordnete Elemente) werden aus `root` entfernt.
Spezialkarten (Karte, Bewertungen, Leistungen und die anderen) sind nicht Teil
dieser Antwort; ihre Position wird mit dem Endpunkt zum Neuordnen unten
festgelegt.
</Note>

Ein paar Felder, die du kennen solltest: `highlightFx` ist ein String, `""`
(keine), `"shake"`, `"shine"`, `"pulse"` oder `"bounce"` (die animierte
Premium-Hervorhebung); `cardSize` ist `"normal"` oder `"wide"` (eine breite
Karte erstreckt sich über beide Rasterspalten); `imageRatio` ist die Bildbreite
geteilt durch die Höhe (`1` für quadratisch); und `order` ist die
Produktposition, die der Katalog-Cursor bei manueller Reihenfolge verwendet.

## Inhalte neu anordnen

```
PUT /v1/content/order
```

Legt die Reihenfolge des Linkbereichs in einem Aufruf fest: Links, Sammlungen,
KI-Assistenten und die Spezialkarten. Die Position jedes Eintrags im Array wird
zu seiner neuen Reihenfolge. Erfordert einen Schlüssel mit dem Scope **write**.
Das MCP-Tool `reorder_content` verwendet dieselben Regeln, und
`get_content_tree` gibt den Baum genau in diesem Format zurück.

### Anfrage

```bash
curl -X PUT \
  -H "Authorization: Bearer lzk_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "root": [
      { "type": "link", "id": "507f1f77bcf86cd799439011" },
      { "type": "section", "key": "services" },
      {
        "type": "collection",
        "id": "507f1f77bcf86cd799439020",
        "children": [
          { "type": "link", "id": "507f1f77bcf86cd799439012" },
          { "type": "ai_assistant", "id": "507f1f77bcf86cd799439030" }
        ]
      },
      { "type": "section", "key": "reviews" },
      { "type": "section", "key": "map" }
    ]
  }' \
  https://api.linkz.ee/v1/content/order
```

### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
| --- | --- | --- | --- |
| `root` | array | Ja | Einträge der obersten Ebene in ihrer neuen Reihenfolge. Darf leer sein. |
| `root[].type` | string | Ja | `link`, `collection`, `ai_assistant`, `section` oder `product` (ignoriert). |
| `root[].id` | string | Außer bei `section` | Die ID des Eintrags. |
| `root[].key` | string | Bei `section` | Die Spezialkarte: `carousel`, `map`, `tips`, `review` (Google-Bewertung), `reviews`, `packages`, `services`, `instagram` oder `social:<network>` (zum Beispiel `social:instagram`). |
| `root[].children` | array | Nein | Untergeordnete Elemente, in Reihenfolge. Wird nur verwendet, wenn `type` gleich `collection` ist. |
| `root[].children[].type` | string | Ja | `link`, `ai_assistant` oder `product` (ignoriert). |
| `root[].children[].id` | string | Ja | Die ID des untergeordneten Elements. |

### Wie der Server den Baum anwendet

- **Unvollständiger Baum.** Links und Sammlungen, die du weglässt, gehen nicht
  verloren: Sie behalten ihren Platz neben ihren alten Nachbarn. Die
  untergeordneten Elemente einer Sammlung, die ohne `children` gesendet wird,
  bleiben, wie sie sind. KI-Assistenten werden nur verschoben, wenn sie im Baum
  sind.
- **Spezialkarten.** Sobald mindestens eine `section` im Baum ist, berechnet
  der Server die Position **jeder** Spezialkarte auf der Seite neu (die Karten,
  die du weggelassen hast, behalten ihren relativen Platz). Ohne `section`
  werden die Karten nicht angefasst.
- **Ungültige Einträge lassen den Aufruf nie fehlschlagen.** Sie werden
  übersprungen und in `warnings` gemeldet:

| Warnung | Bedeutung |
| --- | --- |
| `section_not_on_page:<key>` | Die Karte ist nicht auf der Seite (zum Beispiel keine Kartenadresse). |
| `unknown_item:<id>` | Kein Link und kein KI-Assistent mit dieser ID in deinem Store. |
| `unknown_collection:<id>` | Keine Sammlung mit dieser ID in deinem Store. |
| `media_block_not_in_collection:<id>` | Ein Medienblock kann nicht in eine Sammlung; er bleibt auf der obersten Ebene, direkt danach. |

<Warning>
Zuerst werden die Elemente gespeichert, dann die Positionen der Karten. Im
seltenen Fall eines Fehlers zwischen den beiden Schreibvorgängen sind die
Elemente bereits in der neuen Reihenfolge, und die Karten behalten ihre
vorherige Position; erneutes Senden desselben Baums behebt das.
</Warning>

### Antwort

```json
{
  "error": false,
  "message": "Content reordered successfully",
  "data": {
    "ok": true,
    "warnings": ["section_not_on_page:map"]
  }
}
```

`warnings` ist nur vorhanden, wenn etwas übersprungen wurde.
